# COMPONENTS.md — the component catalog

The canonical list of every reusable component on the site, with its props and
where it's used. **Read this file before creating or updating any page** — the
whole point of the component system is that a visual change is a one-file edit,
and that only works if pages are built from these parts instead of hand-rolled
markup.

- Design tokens (colors, type, radii) live in [DESIGN.md](DESIGN.md) and
  `app/globals.css` — don't hardcode hex or px scales in components.
- The living, rendered version of this catalog is **`/storybook`** — the brand
  voice (BRAND.md), every color token with measured contrast (DESIGN.md), and a
  specimen of every component below, rendered with real content.
- Copy and page data live in `components/content.ts` (and `components/posts.ts`
  for articles) — components take data via props.

## Rules for building pages

1. **Reuse before you build.** Scan the list below; if a pattern exists, use it.
   New UI that duplicates a component's job is a bug.
2. **No inline SVGs.** All icons come from `components/icons.tsx` — that is the
   only file allowed to import `lucide-react` / `simple-icons`.
3. **No hand-rolled pill links.** CTAs and form submits use `Button`. The only
   sanctioned exception (documented in its own file) is the posts ad-break pill,
   a WP-measured one-off.
4. **No bespoke hero shells, page titles, or section headings.** `PageHero`,
   `PageTitle`/`HeroLead`, and `SectionHeading` carry them. Only the homepage
   and give-now titles (their own WP dialects) stay in their pages.
5. **Editing once:** to change how all pills/heads/heroes look, edit the
   component — never sweep the pages.

### Adding a new component (checklist)

1. Build it in `components/` (server) or `islands/` (hydrated, `"use client"`),
   props over hardcoded content. The class prop is `className` (React).
2. Adopt it everywhere the pattern occurs — don't leave inline copies.
3. Add a specimen to `app/(site)/storybook/page.tsx` with real content.
4. Add it to the table below. Steps 3–4 are enforced:
   `app/(site)/storybook/storybook_test.ts` fails when an exported component has
   no specimen or no backticked entry here.
5. `pnpm check` + `pnpm test` + dev-server eyeball of every affected route.

### Icons — `components/icons.tsx`

The single seam for every glyph. Stroke UI icons from **lucide** (`CloseIcon`,
`MenuIcon`, `ChevronLeftIcon`, `ChevronRightIcon`, `PlusIcon`, `MailIcon`,
`CoffeeIcon` — sizes in px, stroke semantics preserved) and filled brand glyphs
from **simple-icons** (`BrandIcon` with
`name="facebook" | "instagram" | "youtube"`). Nothing else imports an icon
package.

## Known gaps (deliberate follow-ups)

- **Forms backend** — every form (`ContactForm` ×2, `NewsletterForm`,
  `TaxDeductibleForm`) shares the `MailtoForm` island, so all of them open a
  composed email today. When PayMongo/a form backend lands, swap its submit in
  that one place. The volunteer signup (`app/(site)/signup/actions.ts`) is the
  exception: it is the first server-handled form, forwarding to the volunteers'
  Google Form so responses stay in their existing Google Sheet — when a real
  form backend lands, it should absorb that hop too.
